# SEC/OPS Gate 1B.2-A — crawler threat model

This register uses only repository-visible code, manifests and prior synthetic
test evidence. Boundary numbers refer to the [architecture baseline](SEC_OPS_GATE_1B2_A_ARCHITECTURE_BASELINE.md).
`TESTED` describes a specific tested behavior, not production network or
container enforcement. Severity is a planning priority, not a measured exploit
likelihood. The [roadmap](SEC_OPS_GATE_1B2_ROADMAP.md) gives gate-level criteria.

| ID / priority / threat | Boundary; existing protection and evidence | Residual risk and required property | Verification method; remediation gate |
|---|---|---|---|
| T1 High — SSRF through URL, redirect or DNS rebinding | 5–6. `url_validator.py`, `dns_guard.py`, `http_transport.py` reject IP literals, reserved hosts, non-global DNS answers and unsafe redirects; synthetic URL/DNS/transport tests cover these paths. | A compromised worker or bypass of Python checks can reach internal, metadata or Docker endpoints because Compose has no egress policy. Require network-layer deny of internal/reserved destinations while permitting intended DNS, DB and web paths. | Inspect effective network policy and run controlled synthetic denied-destination/redirect/DNS tests in a disposable runtime; D, E. |
| T2 High — API compatibility crawl bypasses worker sandbox and queue | 1, 5–6. `prospecting.py` route `POST /companies/{company_id}/enrich` calls `verify_and_extract()` directly; tenant permission applies. | API process may fetch untrusted sites with API credential/privileges and outside worker admission, lease and attempt ledger. Require every deployed crawl path to cross the same isolated execution boundary or disable this route with an explicit compatibility decision. | Route inventory and API contract tests proving no live API-process fetch; B, E. |
| T3 High — compromised worker reads or writes other tenants' data | 4, 7. Repository tenant/company predicates, composite FKs and lifecycle tenant tests cover normal calls. | Worker claims globally and has a SQL URL whose grants are unknown; no RLS. A worker with arbitrary SQL can bypass predicates. Require least-privilege DB identity and explicit tenant isolation decision that covers global claims and session context. | Inspect grants/role attributes; adversarial SQL tests for cross-tenant reads/writes and ownership bypass; C, E. |
| T4 High — worker escape or host resource exhaustion | 5, 10. Compose declares UID 10001, read-only root, cap drop, no-new-privileges, 16 MiB tmpfs, PID 64, memory 512 MiB, CPU 1, no host/socket mounts. | Effective runtime is uninspected; no FD/socket/swap bound, explicit seccomp profile or absolute job deadline. Require enforced identity/mount/cgroup/process/file limits and bounded termination. | Inspect running disposable container and stress bounded synthetic tasks, then assert cleanup and lease recovery; B, E. |
| T5 High — credential exposure or broad SQL authority | 3–4, 10. `config.py` rejects placeholder `SECRET_KEY` when `APP_ENV=production`; crawler requires `CRAWLER_DATABASE_URL`; events exclude tokens. | Secrets arrive through environment; no store/rotation or role issuance evidence. Compose local DB bootstrap user is used by app defaults. A worker credential can be overprivileged or leak through process diagnostics. Require distinct roles, scoped grants, safe injection, rotation and redaction tests. | Static secret inventory without values; disposable role and log tests, effective deployment secret inspection; C, D, E. |
| T6 Medium — retry/cancellation abuse or duplicate external call | 3–4, 7. Advisory lock, five-attempt bound, lease fencing, cancellation and rollback tests in R3-A/B/C; R3-D synthetic receiver test shows two calls and one keyed effect. | External side effects can repeat; a busy or blocked task has no absolute job deadline. Require bounded execution and downstream idempotency/compensation, preserving five attempts and terminal state. | Kill/cancel/expire at each boundary and assert one committed result, no sixth attempt, no stale write; B, D, E. |
| T7 Medium — queue, HTTP and cache saturation across processes | 3–5. R3-C proves 10,000 global/100 tenant **API admission** thresholds; crawler admission and robots tests prove per-loop limits. | `postgres.py` recovery requeues expired jobs without checking queued counts, so a full queue may exceed either cap. Transport budgets are not distributed; many processes multiply concurrency. API synchronous route bypasses queue. Pool overflow and aggregate DB connections have no hard verified ceiling. Require a recovery-safe global/tenant queue policy and deployment-wide budgets. | Saturate queue, expire an active lease, recover without loss or cap breach; measure multi-process connections/FDs under fixed limits; B, D, E. |
| T8 Medium — malicious website content or robots behavior | 5–6. `company_enrichment.py` extracts limited email/phone facts from a 500,000-byte body; robots parser denies malformed/401/403/5xx failures as coded. Synthetic tests cover content type, malformed HTML, robots failures and cache bounds. | HTML/headers remain untrusted, parser is intentionally not a full robots standard implementation, and content can contain sensitive/poisoned facts. Require bounded parsing and source provenance; do not treat website content as instructions or trusted identity. | Synthetic malformed/oversize/redirect/robots cases and source-data inspection; D, E. |
| T9 Medium — diagnostic loss or sensitive logging | 8. `events.py` allowlists IDs/outcomes and catches logger failure; R3-D trace reconstructs tested transitions. Admission/cancel audit rows and attempt ledger are durable. | Diagnostic events may precede rollback and have no verified sink, ACL or retention; they cannot serve as transactional audit proof. Other process logging policy is not verified. Require durable authoritative trace and bounded redaction/retention. | Force logger failure and rollback, compare ledger/job/audit rows with logs, inspect sink/retention; D, E. |
| T10 Medium — CI/deployment drift or supply-chain substitution | 9–10. CI has `contents: read`, isolated PostgreSQL 16 preflight and migration check; run `44818269214` passed 47 integration tests. | Actions/images use tags, Python dependency ranges resolve at run time, no SBOM/image scan; no production deployment manifest or runtime attestation. Require reproducible artifacts, pinned trusted inputs and effective-policy evidence. | Review lock/digest provenance, dependency/image scan output and a disposable deployment attestation; D, E. |
| T11 Medium — privileged SQL bypasses integrity/admission | 3–4, 7. App uses shared advisory key, row locks, unique constraints and composite FKs; R3-C covers concurrent API and claim behavior. | Direct SQL writers can ignore advisory lock and queue counts, mutate statuses or erase jobs. Require restricted application/worker roles and protected migrations; RLS alone cannot enforce numeric caps. | Negative SQL privilege tests and concurrent admission/claim regression under the intended roles; C, E. |

## Explicit security requirements

1. Preserve Gate 1B.1-R3 queue, active, attempt, ledger, lease, cancellation,
   recovery, tenant-interface and transactional-result invariants under the
   final runtime roles and network policy.
2. Remove the deployed synchronous crawl bypass or prove it shares the same
   isolated worker boundary, without silently changing client contracts.
3. Treat the database ledger and job rows as authoritative. Diagnostics are
   redacted and correlated but do not imply commit or exactly-once effects.
4. Keep URL/DNS/robots controls as defense in depth beneath an enforced egress
   policy; account for both IPv4 and IPv6, DNS and redirect revalidation.
5. Verify effective controls on a disposable runtime before any production
   claim. No threat in this register is marked remediated by documentation alone.
