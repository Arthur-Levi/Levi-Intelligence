# Gate 1B.2-B.5 integrated runtime baseline

The branch began at B.4 final commit `fb26739428aa406031c3e77cfad3aeee557a2d51`, synchronized with origin. GitHub Actions run `44947873557` succeeded. No B.5 files existed. The untracked `frontend/tsconfig.tsbuildinfo` is preserved.

The disposable host reports two CPUs, 7.8 GiB RAM with about 6.0 GiB available at setup, Docker Engine 29.9.2-2, cgroup v2 and zero swap. Four workers at one CPU quota each can contend for two host CPUs; concurrency evidence will use held synthetic children and measured throttling. The disposable PostgreSQL 16 server has `max_connections=100`. Its test identity and Alembic head were verified through `scripts/postgres_ci.py` before seeding. A Docker named volume retains data across a server stop/start. The isolated Docker network has no public crawler target.

The test-only image is built from the unchanged backend Dockerfile and copies a synthetic service into the image. Worker containers require no host bind mount or Docker socket. The synthetic service permits only `https://synthetic.example.test`, with bounded mode/identity paths and explicit held, finished, stalled, CPU-bound and crashing behaviors. The seed/inspection helper checks the exact disposable PostgreSQL identity before every action. It created five synthetic tenants, ten jobs (eight held attempts, a third job in the first tenant, and a ninth job in the fifth tenant); inspection showed ten queued, zero running and zero attempts.

The accepted Compose worker configuration is concurrency 2, pool size 2, overflow 0, two-second pool checkout, three-second connect, one-second lock, five-second statement, six-second driver command and 15-second repository transaction budgets. Four workers therefore have a maximum of **eight worker database connections**, plus separate test-harness/API/administration connections. With `max_connections=100` and three reserved superuser slots, the worker pool ceiling consumes at most eight of 97 ordinary slots. The accepted runtime ceiling per worker is 512 MiB memory and matching swap limit, one CPU, 64 PIDs and 1,024 file descriptors; UID/GID 10001, read-only root, 16 MiB restricted `/tmp`, all capabilities dropped and no-new-privileges. Effective cgroups and actual usage still require runtime measurement.

The initial test database and image are disposable. Cleanup will stop/remove only B.5 containers, remove the B.5 named database volume and isolated network after evidence is recorded, and leave repository user files untouched. Production, development and arbitrary public databases or websites are outside this topology.
